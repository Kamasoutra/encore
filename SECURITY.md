# Security

Clipboard history can contain sensitive data. encore excludes common password managers and pasteboard content marked confidential or temporary by default, but cannot reliably detect every secret. Browser extensions may omit these markers. Exclude the host application when needed.

Since 0.7, the library and its contents can be encrypted on disk with ChaCha20-Poly1305, under a 256-bit key kept in the login keychain (Settings → Data). It is off by default: without an Apple Team ID, the keychain ties the item to each build, so macOS asks for the user's password after every update. It will be on by default once encore is signed by Apple. In memory only mode (Settings → Data), only favorites, snippets and collections are written to disk; other copies live in memory and are lost when the app quits. encore's windows use `NSWindow.sharingType = .none` by default, so screen sharing and recording tools that respect it leave them out. Exported JSON backups are not encrypted. Encryption at rest protects copies of the files; it does not protect against software that already runs as the user while encore is open, since encore itself reads the clipboard. Pairing keys for other Macs are kept in a separate file readable only by the user. File references can outlive, or lose access to, their source files.

The optional MCP server is off by default. The `Encore mcp` stdio command starts the containing app without activating a window when needed, then relays requests to it over `~/Library/Application Support/Encore/mcp.sock`; the command never reads the history files or keychain. The app creates this Unix socket with mode `0600` in its private support folder and checks `getpeereid` on accepted connections; the relay also checks the server's user. Other users cannot connect. Processes already running as your user are within this trust boundary: there is no separate per-client authentication, and client names in the log are self-reported. Disabling MCP refuses subsequent requests on existing connections too.

MCP can return text (100,000 characters per page), plain text from rich text, reduced PNG images up to 1568 pixels on either side, OCR text, and referenced file paths and sizes. It never reads the referenced files' contents; PDF text is returned only if already extracted. Secret-marked copies and text matching `SecretKind.detect` are hidden from all MCP reads and counts unless secret access is explicitly allowed, independently of the capture detection setting. Detection remains heuristic and cannot identify every secret, including secrets embedded in ordinary prose or images. Allowing access returns secrets in plain text. Clients may send returned content to their own services: encore's local transport does not control what an assistant does with it. MCP writes are limited to copying, saving snippets and changing favorites, without pasting into the front app or deleting copies. The latest 200 tool attempts, including refusals, are kept in `mcp-log.json` with time, client name, tool and a content-free summary; no arguments, queries, clip identifiers or returned clipboard content are logged. The log can be cleared in Settings → MCP.

The initial release is ad-hoc signed, is not notarized, and has not undergone an independent security audit. Do not rely on encore as a password or secrets manager.

To report a vulnerability, use the repository's private vulnerability reporting feature if enabled. Avoid public reports containing sensitive clipboard data. If private reporting is unavailable, open an issue asking for a private contact route without including the vulnerability details or any personal content.
